# 用户 LUT 与胶卷选择器

`looks/luts/catalog.json` 包含用户上传压缩包的 SHA-256、15 个 LUT 的原始名称、原文件 SHA-256、33³ 网格和显示色。每个 `.cube` 文件保留上传时的字节内容；哈希作为稳定编号，文件名不参与运算。暗盒颜色只用于区分项目，不模拟照片效果。

更新资源：

```bash
python3 tools/import_luts.py /path/to/lut.zip looks/luts
python3 tools/sync_luts.py
```

导入工具只读取 `.cube` 数据，不执行压缩包内的内容。校验路径、文件大小、网格、有限数值、输入范围和数据行数。Android 直接将 `looks/` 作为 assets；鸿蒙使用 `sync_luts.py` 放置的相同 rawfile。协议测试会比较两端资源哈希。

## 照片处理

- 标准 `.cube` 红通道坐标变化最快，然后绿、蓝。
- 输入按 DOMAIN_MIN / DOMAIN_MAX 归一化并钳制到网格范围，缺省为 [0,1]。
- C++ `g23_apply_lut` 对八个邻点做三线性插值，RGB 输出钳制为 8 位，保留 alpha 和行填充。
- 基础调色管线保持 1.0.0；LUT 作为独立的末级 `cube_srgb_trilinear_1.0`，强度为 100%，输入为编码 sRGB。上传文件未附带其他色彩空间声明，未添加推测的 Log 转换。
- 拍摄开始时固定 LUT 和画幅；保存完整成片后返回相机。原 JPEG 不覆盖。
- `look.json`、`look.cube` 与照片一起保存并纳入 metadata/manifest 校验；JSONL 引用 look 和 lut。修改全局胶卷选择不修改旧照片绑定。
- 预览编辑、完整保存、导出重建均由原 JPEG 加基础参数再套一次绑定 LUT，防止反复叠色。旧样本没有 look 时不应用 LUT。

## 交互

右侧半圆轮盘循环展示全部 15 项，屏幕可见范围显示相邻暗盒。左侧箭头与当前暗盒的中线对齐，半圆内部同步显示名称及编号。拖动保持连续位移，松手根据速度做有限惯性滚动，再以短回弹动画吸附到整数档位。每次跨越档位请求一次触觉反馈，并限流防止密集震动；Android 使用系统 SEGMENT_TICK / CLOCK_TICK，尊重系统触觉设置。

相册仅含照片网格与全屏浏览；实验调色、数据和导出入口移到相机设置。

## 验证边界

主机测试比较所有 15 个真实上传 LUT 与独立插值参考，包含通道顺序、边界、输入范围、alpha/stride、损坏数据、重复渲染和真实 JPEG/PNG/ZIP 流程。Android 原生视图测试检查滑动后的名称、触觉请求、档位定位、顶部入口和仅照片网格。签名和编译证据不能代替真机相机、处理耗时和震动手感验收；鸿蒙仍需 SDK 编译。

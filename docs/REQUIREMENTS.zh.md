# G23 Lab — 安卓与鸿蒙双平台实验相机 App 开发任务书

你是一名资深移动端架构工程师、计算摄影工程师、图像处理算法工程师和 UI/UX 设计师。

请帮我开发一款名为 **G23 Lab** 的实验性相机 App。

它不是普通的美颜相机，也不是简单叠加滤镜的 App，而是一款用于研究、记录和训练自定义摄影色彩风格的专业工具。

项目最终目标是：通过大量人工调色样本，建立一个能够自动模拟指定影像风格的相机系统。

首期视觉方向参考 RICOH GR III 的 Positive Film（正片模式），但最终色彩由用户人工调整决定。暂时不开发 AI 自动调色模型，第一阶段先完成高质量的样本采集、参数化调色和 AI 数据导出功能。

## 一、项目核心要求

### 1. 双平台兼容

必须支持：

- Android 原生应用
- HarmonyOS NEXT 原生应用

两个版本都必须能够真实调用设备摄像头，完成预览、对焦、拍照、保存和拍摄后调色。

不得使用网页模拟拍照、静态相机图片或不可执行的相机占位代码替代真实能力。

Android 推荐使用 Kotlin + CameraX / Camera2。

鸿蒙使用 ArkTS + ArkUI + Camera Kit，遵循鸿蒙原生应用开发规范。

两端分别实现相机与系统交互接口，共用图像处理算法、调色参数定义、样本数据格式及数据导出协议。

推荐把核心图像处理模块使用 C++ 实现，通过各平台适当的原生桥接调用。

如果某个功能受设备或系统 API 限制，必须进行运行时能力检测，提供明确降级方案，不得假装已经实现。

### 2. 项目工程要求

需要建立：

- Android 原生工程
- HarmonyOS NEXT 原生工程
- 共用图像处理模块
- 共用调色参数数据模型
- 样本管理模块
- 数据导出模块
- 自动化测试
- 项目说明文档

使用清晰、可维护、便于扩展的模块化架构。

优先实现真实可运行的功能，再进行 UI 美化。

## 二、应用主界面

App 分为三个主要页面。

### 页面 A：Camera 拍摄

进入应用后默认打开原生相机实时取景页面。

功能：

1. 实时显示摄像头预览。
2. 点击快门拍照。
3. 点击画面指定位置对焦。
4. 前后摄像头切换。
5. 闪光灯开关（设备支持时）。
6. 曝光补偿调节（设备支持时）。
7. 网格线开关。
8. 3:2、4:3、1:1 拍摄比例选择，明确区分原生输出比例与裁切。
9. 显示当前设备的摄像头能力。
10. 优先以高质量模式拍照。

如果设备支持 RAW：

- 可选 RAW + JPEG 同时保存。
- 不支持时自动使用高质量 JPEG 或其他已确认可用的格式。
- 不允许伪造 RAW 文件。

首期拍摄照片不自动添加 GR III 风格。

保留手机原生摄像头采集的图像，作为后续人工调色的输入样本。

注意：第三方相机 API 不保证完全复现手机自带相机 App 的专有 HDR 和图像处理效果，不得把两者视为相同。

### 页面 B：Editor 调色

用户拍照完成后，自动进入图片编辑页面。

页面结构：

顶部：
- 返回按钮
- 原图与调色结果对比按钮
- 撤销
- 重做
- 重置
- 保存按钮

中部：
- 大尺寸图片预览
- 支持双指放大、缩小
- 支持拖动查看局部
- 长按查看原图
- 支持滑动分割线比较调色前后
- 显示当前图片信息

下部：
- 横向调色工具分类菜单
- 参数滑块与数值
- 参数恢复默认按钮
- 参数调整实时预览

最下方：
- 可展开的数据记录面板
- 显示当前照片的完整调色参数
- 支持复制 JSON
- 支持查看原图与成片对照
- 支持保存当前样本到训练数据集

所有调色操作都必须可撤销、可恢复、可保存、可重新编辑。

## 三、完整调色系统

请实现以下功能，不允许只制作滑块 UI 而没有真实图像处理效果。

### A. 基础调色

- 曝光 Exposure
- 对比度 Contrast
- 高光 Highlights
- 阴影 Shadows
- 白色色阶 Whites
- 黑色色阶 Blacks
- 色温 Temperature
- 色调 Tint
- 自然饱和度 Vibrance
- 饱和度 Saturation

曝光建议采用 EV 单位。

其余参数可以采用 -100～+100 的界面范围，但需要定义明确的内部映射公式，不得将 UI 数值直接当作未定义的图像运算参数。

色温应明确是相对于原始白平衡的调整量，不得把无校准的滑块值直接标注成绝对 Kelvin。

### B. HSL 色彩调整

需要提供 8 个独立颜色通道：

- 红色 Red
- 橙色 Orange
- 黄色 Yellow
- 绿色 Green
- 青色 Cyan
- 蓝色 Blue
- 紫色 Purple
- 洋红 Magenta

每个通道均支持：

- Hue 色相
- Saturation 饱和度
- Luminance 明度

需要实现平滑的颜色权重过渡，避免不同色相区域出现突兀边界、断层或色带。

### C. 曲线工具

支持：

- RGB 总曲线
- Red 红色曲线
- Green 绿色曲线
- Blue 蓝色曲线

功能：

- 自由添加控制点
- 拖动控制点
- 删除控制点
- 重置曲线
- 保存控制点数据
- 支持曲线配置复用

需要使用平滑、连续且受控的插值算法。

### D. 色彩分级 Color Grading

提供三个影调区域：

- Shadows 阴影
- Midtones 中间调
- Highlights 高光

每个区域都支持：

- 色相
- 饱和度或调色强度
- 明度调节

另外支持：

- Balance 平衡
- Blending 混合范围

需要定义可复现的影调区域权重和混合算法，避免明显色彩断层。

### E. 图像质感 Texture

支持：

- Sharpness 锐度
- Clarity 清晰度
- Local Contrast 局部对比度
- Grain 颗粒强度
- Grain Size 颗粒大小
- Vignette 暗角
- Fade 褪色

锐化应尽量避免明显光晕。

颗粒生成需要支持固定随机种子，确保同一照片及同一参数重复渲染时结果一致。

### F. 调色预设

支持：

- 保存当前调色方案
- 给预设命名
- 编辑预设
- 删除预设
- 一键应用预设
- 导入、导出预设 JSON

预设只包含调色规则，不覆盖原始照片。

## 四、非破坏性图像处理架构

这是技术上的强制要求。

所有编辑必须基于原始图像或统一的高精度工作图像进行计算。

不允许每调整一次参数，就把压缩后的上一帧作为下一次调色输入。

推荐建立明确的处理顺序：

1. 图像解码和方向归一化
2. 输入色彩空间转换
3. 白平衡与曝光
4. 基础影调
5. RGB 曲线
6. HSL 调整
7. 色彩分级
8. 清晰度、局部对比度及锐度
9. 颗粒与暗角
10. 输出色彩空间转换
11. 导出 JPEG / PNG

实际开发时可以根据数学性质合理调整部分步骤，但必须记录固定的处理顺序及版本。

确保：

- 实时预览与最终导出使用同一组参数和算法。
- 预览可以使用低分辨率加速。
- 最终输出尽量采用完整分辨率处理。
- 尽可能在高精度工作空间中完成计算。
- 正确处理图片方向与 ICC 色彩信息。
- 不发生不必要的重复 JPEG 压缩。
- 相同输入、相同参数和相同算法版本能生成可重复的输出。

## 五、参数实时记录系统

这是整个项目最重要的模块之一。

用户每调整一个参数，都必须在底层数据模型中更新对应数值。

调色结束后，系统必须保存完整的参数快照。

数据记录面板在编辑页面最下方，可以展开或收起。

面板包含：

### 1. 当前样本信息

- 样本编号
- 拍摄日期和时间
- 设备品牌
- 设备型号
- 操作系统
- 摄像头标识
- 原始图片尺寸
- 原始图片格式
- 曝光时间
- ISO
- 光圈（能获取时）
- 焦距及等效焦距（仅在可靠获取时）
- 原始白平衡信息（能获取时）

### 2. 参数记录

完整保存所有调色参数。

包括：

- 基础调色
- HSL 八色通道
- RGB 曲线控制点
- 色彩分级
- 质感参数
- 图像裁切与旋转信息
- 渲染管线版本

### 3. 图片前后对照

保存：

- 原始图片
- 调色后最终图片
- 用于快速浏览的前后对照缩略图

原图必须保留，不允许覆盖。

### 4. 调色历史

实现：

- 参数修改历史
- 撤销和重做
- 最终参数快照
- 可选编辑过程导出

编辑历史与最终参数快照应当分开存储。

后续 AI 默认学习最终确认的参数快照，而不是自动把每一步试错都当作训练标签。

### 5. 样本确认

调色完成后，用户点击：

【保存为 G23 训练样本】

系统保存一条完整记录。

只有明确确认的版本才标记为 approved。

对于尚未完成的调色，保存为 draft。

## 七、AI 数据导出规范

必须支持批量导出为 ZIP 数据集。

文件结构：

G23_Dataset_Export/
- manifest.json
- dataset.jsonl
- samples/
  - G23_000001/
    - original.jpg
    - original.dng（可选）
    - edited.png
    - thumbnail_before.jpg
    - thumbnail_after.jpg
    - parameters.json
    - metadata.json
  - G23_000002/
    - ...
- reports/
  - dataset_summary.json
  - parameters_summary.csv
- README.md

其中：

### original.jpg
保存调色前的原始拍摄图像。

### original.dng
仅当设备支持并实际获得 RAW 时存在。

### edited.png
保存完整分辨率的调色结果，优先采用无损格式作为 AI 学习目标。

### parameters.json
保存全部最终调色参数、处理顺序、参数单位及算法版本。

### metadata.json
记录设备信息、拍摄环境、评分和文件校验信息。

### dataset.jsonl
一行一个训练样本。

每行包含：

- 样本 ID
- 原图相对路径
- 成片相对路径
- 参数文件相对路径
- 场景标签
- 设备型号
- 质量评分
- 是否确认
- 处理管线版本

禁止在 JSONL 中直接嵌入大型图片的 Base64 数据。

### parameters_summary.csv
建立参数汇总表。

每行一张照片，每列一个参数，例如：

sample_id, exposure, contrast, highlights, shadows, saturation, red_hue, green_hue, blue_hue, grain 等。

对于 RGB 曲线等可变长度数据，可使用单独 JSON 文件记录详细结构，并在 CSV 中提供相应文件引用。

### 数据质量要求

- 每条样本必须有唯一 ID。
- 不允许原图和成片错配。
- 保留参数版本。
- 对文件计算 SHA-256 校验值。
- 支持检查缺失文件。
- 支持检查重复样本。
- 支持导出前验证。
- 导出必须有进度展示。
- 大量图片导出时避免内存溢出。
- 支持选择仅导出 approved 样本。
- 支持导出完成后通过系统分享功能保存 ZIP 文件。

还应提供一个可供后续 Python AI 训练程序直接读取的示例脚本，用于：

1. 读取 dataset.jsonl。
2. 找到原图与目标图。
3. 加载对应调色参数。
4. 验证文件完整性。
5. 统计不同参数的分布。
6. 生成原图与成片的对照报告。

## 十三、现在开始执行
